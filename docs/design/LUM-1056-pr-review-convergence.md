# PR review convergence (LUM-1056)

Automatic AI discovery is bounded by a durable per-PR budget. Since LUM-1137 it follows the industry-standard model (review every push, pause after N reviewed commits): every push to an open PR is reviewed incrementally until the PR has N reviewed commits, where N is the PR's own limit (`--resume --limit`, `@uselumo resume`), else the workspace's `securityReviewAutoPauseAfter` (default 5; 0 = never pause). Reviewed commits are counted by commits rather than pushes (the industry-standard way): each admitted head records the PR's commit count at that head (`reviewHeadCommits`, read from the pulls API for that exact head), and contributes the commits it added since the previous admitted head — one commit for the first automatic review of the PR (not every commit already on it, so a PR opened with N or more commits still gets N automatic reviews), at least one for any head (a force-push that shrank the PR still reviewed a new head; an unknown count is one). LUM-1056 counted distinct admitted heads against a default of two. On top of the budget, an hourly cap per PR author in the workspace (20 automatic reviews, a sliding window; industry-standard per-developer limits are 5–12 per hour by plan, but Lumo's agents push under one identity) keeps a push storm from exploding cost: a new head over the cap is not reserved, its AI layers are stored `PAUSED` with partial cause `AI_REVIEW_RATE_LIMITED` and every surface says "rate-limited — automatic review resumes within the hour"; the next push after the window is admitted normally. Only a new head is counted against the cap; retries of an admitted head and manual reviews never are. Reservations are made in a serializable transaction after the diff is proven to belong to the head and before model work; failed attempts retain their reservation and retrying an admitted head costs no additional round. The exception is a head superseded by a newer push before its review is persisted: its round was never delivered, so it is released. Explicit pause overrides retries. Resume clears the reservations, records a baseline at the PR's current commit count (a `resume-baseline` entry in `reviewHeads`/`reviewHeadCommits` that counts nothing; omitted when GitHub cannot report the count, in which case the next head is the first review and counts one), and optionally changes the limit (1–100); the next head is charged only for the commits added since the resume, so a resumed PR gets its full N-commit budget again. On top of the budget, only a head that was actually reserved takes a slot of the hourly cap: the cap is checked after the reservation, and a head over the cap has its reservation released. A manual incremental or full review bypasses the budget without resetting it. Both AI review and exploit-path discovery pause; deterministic secrets, graph rules and managed scanners continue.

The baseline is the latest finished, non-partial scan with an untruncated, successful AI review and no pending verifier. GitHub compare must confirm a forward history and a complete file list. Divergent history, missing baseline or a 300-file comparison falls back to a complete PR review. Incremental review includes the PR diff sections of affected files, preserving PR-head line numbers and existing changed-file context. This is file-level incremental review, not a claim to analyze only newly added lines. Head changes during diff retrieval or before persistence fail that attempt rather than publishing another commit’s code as reviewed.

Prior AI findings retain their fingerprints and dispositions. Missing from an incremental diff is not a fix. A finding closes when a complete (untruncated) judge pass re-reviewed its file — every file in a full review, the compare paths in an incremental one — and did not report it again; a paused, failed or truncated judge closes nothing. The existing verifier may explicitly reject non-HIGH correctness findings; security and HIGH findings remain subject to the existing human disposition policy. Paused reviews do not invoke the verifier. Other unfinished layers still report their failures. A paused layer cannot render the scan as checked, but it is not described as an infrastructure failure. Existing DONE policy continues to gate blocking security findings; pausing does not clear those findings or add a new AI-coverage gate.

`lumo pr scan N --repo owner/repo --review incremental|full` requests a manual review. `--pause` pauses; `--resume [--limit N]` resumes with a fresh budget. The task scan panel exposes the same actions. Manual review of a terminal head claims it inside the existing serializable restart transaction; active asynchronous layers or an active verifier prevent restart. Concurrent requests deduplicate while work is running. A later explicit request after completion is a new review. Late GitHub write-back checks the PR’s recorded current head in addition to scan ordering.

Human-ruling snapshots and the same-head manual claim share one serializable transaction. Existing findings remain on that row while manual work runs and are replaced atomically only on successful persistence; a failed manual attempt cannot erase a human ruling.

Deployment requires the additive PullRequest migration before application rollout. Existing PRs begin with a fresh two-round budget; historical reviews do not consume that budget.

LUM-1137's migration is additive: `Workspace.securityReviewAutoPauseAfter` (default 5, CHECK 0–100), `PullRequest.reviewHeadCommits` (default empty) and the nullable `PullRequest.reviewCommitLimit` (CHECK 1–100). A PR whose `reviewRoundLimit` is not the old default 2 had it set explicitly by `--resume --limit`, so it is copied into `reviewCommitLimit` and stays that PR's limit; every other PR — including open PRs with heads already reserved — adopts the workspace setting at read time, and its earlier heads count one commit each. `reviewRoundLimit` is no longer read; LUM-1138 stopped mapping it (#1478) and then dropped the column.
